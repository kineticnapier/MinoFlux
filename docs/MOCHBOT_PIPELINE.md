# Mochbot-style AI pipeline

MinoFlux 0.10.0 contains the first opponent-aware and replay-data stages needed for a mochbot-style agent. It does not claim to reproduce mochbot yet.

## Implemented foundation

- exact SRS-reachable placement generation
- exact T-spin Mini, Single, Double, and Triple classification
- Hold, B2B Charging, Surge release, garbage packets, cancellation, and blocking
- player-versus-AI client
- opponent-aware action scoring
- one opponent-reply search layer
- deterministic headless versus benchmarks
- TETR.IO placement-capture import
- exact captured-board to SRS-route alignment

## Opponent-aware search

`choose_versus_action` scores a complete `VersusMatch`, not only the active board. It includes:

```text
own and opponent board height
own and opponent holes
own and opponent pending garbage
attack sent and garbage canceled
own and opponent B2B chain
own and opponent Surge charge
input-path length
win / loss state
```

It can evaluate a bounded set of the opponent's immediate replies and chooses the root action with the best worst reply.

Interactive example:

```powershell
start-versus.bat --ai-pps 1.0 --ai-candidates 8 --ai-reply-width 2
```

Headless model comparison:

```powershell
uv run minoflux versus-benchmark `
  --games 10 `
  --max-turns 500 `
  --player-model data/models/champion-cem.json `
  --ai-model data/models/candidate-cem.json `
  --candidate-width 8 `
  --reply-width 2 `
  --lookahead-pieces 0 `
  --beam-width 2 `
  --save
```

The benchmark alternates the starting side and reports wins, attack, uncanceled sent garbage, cancellation, received garbage, maximum B2B, and maximum Surge.

## TETR.IO capture input

The importer accepts the `tetrio-placements-*.json` output generated by the replay-capture extension. Known fields are:

```text
username, gameid, round, sequence
pieceIndex, piece, x, y, rotation, frame
hold, holdLocked, next, seed
capturedAt, board
operations / inputs / path / moves when present
```

The 40x10 capture board is preserved and its bottom 24 rows are also used as the MinoFlux board representation. Garbage cell names such as `g` and `gb` are retained.

Convert one capture:

```powershell
uv run minoflux import-tetrio-capture `
  "C:\path\tetrio-placements-1784556184795.json" `
  --username mochbot `
  --output data/datasets/mochbot.jsonl `
  --align-out data/datasets/mochbot-alignment.jsonl
```

Outputs:

```text
data/datasets/mochbot.jsonl
  grouped state/action observations

data/datasets/mochbot.summary.json
  users, rounds/games, split counts, and transition confidence

data/datasets/mochbot-alignment.jsonl
  exact or ambiguous SRS route matching for board transitions

data/datasets/mochbot-alignment.summary.json
  exact/ambiguous/unmatched counts and alignment rate
```

## Leakage-safe dataset split

Rows from the same player/round/game are never split independently. The complete group

```text
username | round | gameid
```

is assigned deterministically to train, validation, or test. This prevents nearly adjacent boards from the same round appearing in both training and validation.

## Board-transition alignment

When two consecutive captured placements for one player have a clean transition, MinoFlux reconstructs the previous board, enumerates legal SRS paths, applies each candidate, and compares the result with the captured next board.

Alignment status:

```text
exact            one SRS candidate reproduces the board
ambiguous        multiple routes reproduce the board
unmatched        no MinoFlux route reproduces the transition
no-before-board  first observation in a group
```

Incoming garbage, capture gaps, rule differences, or missing Hold/queue information can produce an unmatched transition. Raw coordinates and boards remain in the dataset even when alignment fails.

## Capture limitations

The existing placement JSON primarily records post-lock board states. It is already suitable for placement imitation and board-transition reconstruction, but exact physical key timing requires the extension to export the replay operation stream as `operations` or `inputs`.

For best training data, the extension should emit per placement:

```json
{
  "operations": ["moveLeft", "rotateCW", "hardDrop"],
  "operationFrames": [120, 122, 126],
  "holdUsed": false,
  "pendingGarbage": 4,
  "attackSent": 2,
  "b2b": 17,
  "surge": 17
}
```

The importer is forward-compatible with an operation array, but the additional timing and versus-state fields still need to be added to the extension output schema.

## Next implementation stages

1. Train a supervised placement-ranking model from aligned captures.
2. Use that model to prune SRS candidates before versus search.
3. Add a learned state-value head for B2B maintenance and Surge release timing.
4. Add bitboard state, transposition caching, and batched inference.
5. Train with a league of historical agents rather than one fixed opponent.
6. Add PPS/input-budget constraints and lock-delay-aware route feasibility.
7. Promote models by unseen-seed versus win rate, not solo Attack alone.

The supervised stage should predict a distribution over legal placements rather than raw coordinates. This guarantees that the learned policy is used only to rank actions already verified by the MinoFlux SRS generator.
